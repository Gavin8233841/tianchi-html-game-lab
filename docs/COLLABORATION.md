# 日常协作

共享规则见根目录 AGENTS.md。本文件是 Agent 的操作参考，队员不必记命令。每人一个 GitHub 账号、一个本地副本；同一个仓库、每个任务一个分支，不默认 Fork。

## 开工与领取任务

1. `git status --short`，核对分支与 origin，`git fetch origin`。
2. 看 [Issues](https://github.com/Gavin8233841/tianchi-html-game-lab/issues) 和 [PR](https://github.com/Gavin8233841/tianchi-html-game-lab/pulls)。用户已指定任务时直接续做；新独立功能在 Issue 留简短认领，写范围和分支。看见别人已做同一块就拆分或排顺序，不各自重做。
3. 新任务用 `git switch -c task/<login>/<topic> origin/main`。名字里的 login/topic 必须替换为实际值，不把尖括号原样执行。现有任务看 PR 是否已合并，未合并继续原分支。
4. 技术栈尚未选定。游戏方向确认后，让一个任务搭基础骨架，其他成员先做资料、视觉参考或独立实验，避免三人同时初始化项目。

## 同步和交付

工作完成一个小步 → 跑相关检查 → 检查 `git diff` 和暂存差异 → 明确文件 commit → push 任务分支 → 创建/更新 PR。

- 当前默认 `npm run check`；视觉/玩法还需对应浏览器试玩。初期 CI 只检查预览工具，不证明游戏质量。
- 暂存明确文件，既不漏掉自己的运行文件，也不夹带队友改动。生成物是否提交按实际构建约定决定，当前无构建目录。
- PR：base 为 main，head 为自己的任务分支。长正文用 `.local/` 内 UTF-8 文件配合 `--body-file`，不在 shell 内拼接复杂文案。
- 原型半成品标 Draft；可验收转 Ready。PR 中给出明确运行步骤、结果和检查，功能变更给必要截图；未经部署不虚构线上预览链接。
- 三人的 Agent 均可在检查通过后主动 squash 合并本任务 PR，无需人工验收；检查进行中可开启自动合并。合并后下一项任务从更新的 main 建新分支，不把旧任务无限接长；本地旧分支无需急着删除。
- Agent 结束前比较本地 HEAD 与 upstream，不能只凭 push 命令发出就声称远端已更新。遇到网络错误先保存本地，下次重试。

## 并发和冲突

- 两人尽量修改不同文件或模块；使用同一入口前在 Issue 说清修改范围。普通小任务不必走复杂认领流程。
- 自己的任务分支落后 main：干净工作区内 `git merge origin/main`，保留合并提交。不是在任务分支上 `git pull origin main` 随意改变策略。
- 同一任务分支出现队友提交：fetch 后查看差异，普通合并该远程任务分支；不 force push。
- 冲突先理解双方行为，合并后跑受影响检查；不能机械选整文件任一边。涉及产品取舍时只问具体冲突。
- 本地存在不明修改：不 reset、不 clean、不随手 stash。可以继续不重叠部分；必要时保留现场，说明具体文件和影响。
- PR 已合并后发现错误：新分支修复并追加 PR，保留历史。撤销独立任务用新分支 revert 其 squash 提交，检查后合并，不改写 main；有后续依赖时评估连带影响。

## 常见障碍

| 现象 | Agent 应做什么 |
| --- | --- |
| 能下载但 push 返回 403 | 核对本人账号及写权限，提醒接受队长邀请；保留本地提交 |
| GitHub 登录中断 | 只续做登录与权限检查，不重复安装或克隆 |
| 当前分支是 main 但已有本任务改动 | 保留改动，新建任务分支后再提交 |
| PR 分支已合并 | 新任务从最新 main 开分支；无新任务不做空提交 |
| 用户下次回来不知道上次做到哪 | 先看 git/PR/Issue，再用一句话恢复任务上下文 |
| 队友忘记提交 | Agent 在阶段结束及最终回复前主动处理 |
| 端口冲突 | 换空闲端口，不终止不认识的进程 |
| Qoder 没有浏览器工具 | 验证 HTTP 和检查，标明缺口，请队员点开页面；不冒充截图验收 |
| CI 失败 | 查具体日志修本任务问题；不禁用检查来通过 |
| 新增收费服务/正式部署 | 先准备可审查方案，取得该项授权后执行 |

## 创意与设计记录

创意用 Issue 描述：玩家做什么、核心趣味、最小可玩范围、参考链接。提出想法并不等于批准全部实现。负责人确定方向后才写入 docs/DECISIONS.md。

素材和外部代码在 docs/SOURCES.md 留依据；采用时才下载必要内容。不把整段私人 Agent 对话、账号页面和大量候选包上传公开仓库。

## 每轮同步与主动合并

每次收到新请求先 fetch，查看 main 新提交及开放 PR。安全更新当前分支后简述队友进展；脏工作区先保护修改，无法同步或断网时说明缺口。未合并工作不能当作共同版本已有功能。

任务可交付时，核对最终差异并转为 Ready，然后执行 gh pr merge PR号 --auto --squash --match-head-commit 已核对的HEAD（使用实际值）。main 并发更新时获取、合并并复查受影响部分，推送后必要时重新启用自动合并。不用 --admin 绕过检查。核实 PR 已 merged 和 mergeCommit 后才报告已合入。

每任务保留一条 squash 提交方便 revert。大改动主动提醒影响和回滚方案，不增加固定审批。固定克隆复用，模块按职责适度拆分，临时文件归 .local/；不为整洁丢弃修改或反复新建工作树。
